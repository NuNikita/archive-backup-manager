# GitHub и автоматическая проверка

Проект готовится к размещению в отдельном GitHub-репозитории. Содержимое папки `backup-manager` должно находиться в корне репозитория, чтобы GitHub обнаружил `.github/workflows/ci.yml`.

## Что выполняет конвейер

После отправки изменений в `main`, создания pull request или ручного запуска из раздела Actions выполняются следующие этапы:

1. `test` — проверка форматирования Go, автоматические тесты с настоящими PostgreSQL и restic, поиск статических ошибок и сборка программы. Тесты запускаются с обнаружением гонок данных.
2. `containers` — генерация временных паролей, сборка и запуск пяти сервисов Docker Compose, вход через веб-приложение, резервное копирование, восстановление, сравнение SHA-256 и проверка целостности репозитория. По окончании удаляются только временные контейнеры и тома исполнителя GitHub Actions.
3. `image` — после успешных проверок ветки `main` сборка и публикация Docker-образа в GitHub Container Registry. Тег образа равен идентификатору коммита. Для pull request этот этап пропускается.
4. `deploy` — подготовленный этап обновления VPS, который отключён, пока переменная `DEPLOY_ENABLED` не равна `true`. До покупки и настройки VPS включать его не требуется.

Для проверки и публикации образа отдельный VPS не нужен. Используются предоставляемые GitHub исполнители. Для доступа к GHCR workflow использует автоматически выдаваемый `GITHUB_TOKEN`; пользовательский токен в исходники добавлять не требуется.

## Что исключено из исходников

Файл `.env`, его дополнительные варианты, закрытые ключи, папка `secrets`, локальные исполняемые файлы и восстановленные данные исключены через `.gitignore`. В CI запускается `scripts/setup.py`, который создаёт новые случайные тестовые пароли на время одного запуска.

Перед первым коммитом необходимо проверить состав файлов и убедиться, что текущие реальные пароли из `.env` не встречаются в публикуемых исходниках.

## Как показать результат

В репозитории открыть Actions → Test build and deploy → последний запуск. Успешные этапы `test`, `containers` и `image` должны быть отмечены зелёным. Пропущенный `deploy` до настройки VPS ожидаем и не является ошибкой.

Для курсовой сохранить скриншот общего результата и фрагменты журналов с успешными тестами, восстановлением и проверкой SHA-256. Фактический запуск подтверждается ссылкой на завершённый workflow; наличия YAML-файла для этого недостаточно.
