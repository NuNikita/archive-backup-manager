# План проверки системы

Это сценарии для фактического выполнения и подготовки скриншотов. До запуска стенда они не являются отчётом об успешном прохождении.

| № | Действие | Ожидаемый результат | Материал для отчёта |
| --- | --- | --- | --- |
| 1 | Запустить Docker Compose | Пять сервисов работают, app и db имеют healthy | Список сервисов |
| 2 | Войти как admin | Открывается панель управления | Интерфейс и роль |
| 3 | Ввести неверный пароль | Вход отклонён | Сообщение входа |
| 4 | Войти как viewer | Доступен просмотр, операции изменения отсутствуют | Панель наблюдателя |
| 5 | Отправить изменение с ролью viewer | Сервер отвечает 403 | Тест прав доступа |
| 6 | Создать и изменить задание | Данные сохраняются в PostgreSQL | Форма и таблица |
| 7 | Создать первую копию | Операция success, получен идентификатор снимка | История и снимок |
| 8 | Изменить исходный файл и создать вторую копию | Появилась новая версия | Две версии |
| 9 | Удалить тестовый исходный файл, восстановить первую версию | Файл восстановлен в отдельную папку | Журнал восстановления |
| 10 | Сравнить восстановленное с заранее сохранённым эталоном | Состав и SHA-256 совпадают | Вывод verify_restore.py |
| 11 | Установить хранение двух версий и создать третью | В репозитории осталось две версии задания | restic snapshots и панель |
| 12 | Включить интервал 1 минута | Задание выполнено автоматически | Время запуска и журнал |
| 13 | Остановить storage, запустить копирование | Операция failed, ошибка видна | Журнал ошибки |
| 14 | Запустить storage и повторить операцию | Новая операция успешна | Восстановление работоспособности |
| 15 | Перезапустить app и worker | Настройки и история сохранены | Состояние до и после |
| 16 | Запустить полную проверку хранилища | restic check --read-data завершён успешно | Журнал проверки |
| 17 | Выполнить запуск в Swarm | Видны два узла и сервисы на них | node ls и stack ps |
| 18 | Выполнить CI/CD с настроенной площадкой | Тесты, образ и обновление успешно выполнены | Конвейер и SHA образа |

Для сценария 13 после проверки верните хранилище командой `docker compose start storage`. Для сценария 9 используйте только вымышленные данные из demo-data и заранее сохраните эталон. Снимки, удалённые политикой хранения, восстановлению не подлежат.

Собственные схемы для пояснительной записки: архитектура сервисов; последовательность резервного копирования; последовательность восстановления; модель данных; схема CI/CD. Каждая схема должна описывать реально реализованный процесс.
